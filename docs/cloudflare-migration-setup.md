### D1 schema — ported and verified

All **51 tables / 483 columns** applied to the real D1 database from
`drizzle/d1/0000_baseline.sql`, generated by `scripts/migration/pg-to-d1-schema.mjs` off
production's live catalog. Round-tripped a row to prove it works rather than merely parses.

**The money decision.** SQLite has no exact decimal and REAL would silently corrupt
currency, so all 8 `numeric(p,s)` columns become INTEGER minor units:

| Column | Scale |
|---|---|
| `comp_entries.base` / `.bonus` / `.equity` | cents (×100) |
| `comp_entries.shares` | ×10000 |
| `comp_entries.vest_years` | ×100 |
| `stock_prices.price` | ×10000 |
| `subscription_plans.price_monthly` / `_yearly` | cents (×100) |

This is a breaking change to every read and write of those columns. The ETL multiplies; the
app divides at the presentation boundary, never in the query layer — a missed conversion
misreports a salary by 100×.

Also surfaced: **SQLite cannot generate a UUID**, so every column defaulting to
`gen_random_uuid()` now requires the insert path to supply an id.

Functions, triggers, RLS policies, the materialized view and the GIN index are deliberately
absent — SQLite supports none of them as used here. Their replacements (trigger drain,
app-layer scoping, live aggregate, FTS5) are tracked in the migration plan.

### R2 — 70 of 78 objects migrated

`scripts/migration/supabase-storage-to-r2.mjs` is idempotent, so it serves both the bulk
copy and the cutover delta sync. Keys are preserved verbatim, including the doubled
`resumes/resumes/{uid}/…` prefix that stored `file_url` values depend on.

**8 objects are blocked by a wrangler bug.** `wrangler r2 object put` percent-encodes a key
containing a space while reporting the unencoded name — `put "…/resume 2.pdf"` prints
success but stores `…/resume%202.pdf`, and a later `get` of the real key misses. `put`
encodes, `get` does not, and pre-encoding is neither double-encoded nor decoded, so there is
no CLI workaround. Verified on wrangler 4.56.0.

Only legacy objects are affected: `sanitizeFilename` replaces whitespace with underscores
and is applied on upload, so nothing new can produce such a key.
