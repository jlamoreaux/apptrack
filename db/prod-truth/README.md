# Production schema truth

Generated by `scripts/migration/dump-prod-truth.sh`. **Read-only, schema-only — contains no row data.**

## Why this exists

The repo's `schemas/`, `schemas/migrations/`, `migrations/` and `scripts/*.sql` are three uncoordinated
directories with no migration ledger, and they have demonstrably diverged from production. Examples found:

- `handle_new_user` has six conflicting definitions in the repo; production runs a seventh, simpler one.
- `schemas/migrations/014` defines a materialized view whose `interview_prep` join was later fixed by 017;
  production runs the 017 version.
- `handle_new_user_subscription()` exists in production but is wired to **no trigger** (see `09_*`).

**Treat these files as authoritative. Do not plan schema work against the SQL in `schemas/`.**

## Regenerating

```bash
./scripts/migration/dump-prod-truth.sh   # rewrites this directory
./scripts/migration/prod-checks.sh       # row counts / orphan / auth parity checks
```

Requires `POSTGRES_URL_NON_POOLING` in `.env` or `.env.local`. Production is **Postgres 17.4**, so the
scripts use the v17 client at `/usr/local/opt/libpq/bin/` — the Homebrew `postgresql@14` client will refuse.
